## From zero to store upload in four commands

Run these from the root of your Expo project. The first one needs no install.

```bash
# what is missing on this Mac?
npx rn-shipyard doctor

# one-time signing and Fastlane setup
rn-shipyard init

# expo prebuild + Fastlane gym, output in ./output
rn-shipyard build --platform ios

# upload the .ipa to App Store Connect
rn-shipyard submit --platform ios
```

Build output streams to your terminal as it happens. Android works the same way with `--platform android`, and `--platform all` does both, one after the other.

It reads your existing `eas.json` and `app.json`. It never modifies them.

## rn-shipyard vs EAS

EAS can already build locally with `eas build --local`. The difference is what else it needs from you. Here is the honest picture.

<div class="compare-table">

| | EAS Build (cloud) | `eas build --local` | rn-shipyard |
|---|---|---|---|
| Queue | Shared queue on the free plan, priority on paid plans | None (but needs an account, and marked experimental) | ✓ None |
| Where the build runs | Expo's cloud | Your machine | Your Mac |
| No Expo account needed | ✗ | ✗ (login and a linked EAS project) | ✓ |
| Works offline | ✗ | ✗ | ✓ until the upload step |
| Where submit runs | Expo's servers | Expo's servers (`eas submit`) | Your Mac, straight to the stores |
| Credential storage | Expo manages them | Expo manages them | Yours: Fastlane Match, your own keystore |
| Cost | Free tier with limits, paid plans above it | Needs an Expo account; check Expo's pricing | ✓ Free |
| Needs a Mac for iOS | No | Yes | Yes |
| Windows / Linux | ✓ | – check Expo's docs | ✗ |
| OTA updates | ✓ EAS Update | ✓ EAS Update | ✗ |
| Maturity | Mature | Marked experimental in its help text | New |

</div>

EAS is the better choice when you have no Mac, want credentials managed for you, need OTA updates, or want a mature product with support. rn-shipyard is for people who want a local-first workflow with no account and no lock-in. You can use both: nothing in rn-shipyard changes your EAS setup. See [Migrating from EAS](/guides/migrating-from-eas/).
